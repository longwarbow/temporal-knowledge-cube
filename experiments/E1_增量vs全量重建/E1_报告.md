## 3. 维护代价（操作数计）

- 增量：全流一次通过 = 1278493 事件 × 4 cuboid = **5113972 次单元更新**
- 全量：13 个检查点各重建一次 = Σ 前缀 = **28535936 次单元更新**
- **累积代价比（重建/增量）= 5.6×**
- 单看「增量维护最新 127850 条(10%)」：增量 511400 次 vs 重建 5113972 次 = **10.0×**
- 实测耗时：增量累计 12.36s ｜ 重建累计 40.96s（比值 3.3×）

## 4. 乱序到达鲁棒性

- 将 1278493 条事件**完全打乱**后重放：与事件时间序结果比对 → **✅ 0 差异**
- 意义：聚合量（count / Σlevel / distinct-uid）在**单元层可交换**，故增量维护对到达顺序不敏感；
  但**时间窗内的归属**仍依赖事件时间（双时态的必要性见 RQ1 §3）。

## 5. RETRACT 失效影响集 = 其传播级联（P2 最小重算原型）

- 选中最大级联的种子帖 `AwqYakTJT`：含转发 **965** 条（占全流 0.08%）
- 全立方体 cells = **4626** ｜ 受影响 cells = **51**（1.10%）
- 撤回后「增量（只动受影响 cell）」vs「全量重建」：**✅ 0 差异**
- 代价：增量 = O(受影响) = 3860 次更新 ｜ 朴素全量 = O(N) = 5113972 次更新 = **1325×**

> 说明：`distinct-uid` 采用**精确频次表**（uid→freq）实现，故撤回可**精确删减**（退化为 0 即移除），
