## 1. 结论（先看这一段）

1. **"不用 GPU" 成立**：EraRAG 官方依赖 `faiss-cpu` + OpenAI 兼容 API，**必需 GPU 的步骤 = 0**。全程 CPU。
2. **LLM 凭据可用**，且可被 **EraRAG 原生代码路径**（`Context.llm()` → `OpenAILLM`）直接消费，无需代理层。
3. **此前记录的「本机 Python TLS 被拦」对本端点不成立** —— `openai` SDK 直连成功。该条约束在 E14 上可以不启用。
4. **token 预算初估**：PHEME 全量约需 **prompt 4–8M / completion 0.5–1.5M tokens**；GLM-4-Flash 免费 ⇒ 现金成本 **¥0**。
5. 发现 **3 条官方仓库/生态缺陷**（见 §4），均需写入论文的 artifact-reproducibility 与 Threats 讨论。

## 4. ★ 官方仓库/生态缺陷（3 条）

> 这三条共同说明：**该仓库的 main 分支在本机 Py3.9 下无法开箱运行**。移植口径必须写进论文的 artifact reproducibility 一节。

| # | 位置 | 现象 | 我们的处理 |
|---|---|---|---|
| 1 | `Core/Graph/TreeGraphLSH.py:18-19` | `BUCKET_MAP_FILE = Your Bucket Map File`（**未填完的占位符，裸字符串 ⇒ `SyntaxError`**），而该文件被 `GraphFactory` **顶层导入** ⇒ clone 后直接 `import` 即崩 | 仅"补引号"，**不动算法** |
| 2 | `llama-index` 依赖链 | 仓库钉 `llama-index-core==0.12.23.post2`，pip 会解到 `0.14.16`，引入 `banks 2.5.1`（`MEDIA_ROOT: Path \| None` 在 Py3.9 运行期崩） | 逐个钉死版本并卸载 `banks` |
| 3 | `Config/LLMConfig.py` vs `Core/Common/LLMConfig.py` | **各定义一份 `LLMType` 枚举，二者不是同一个类**。provider 注册表按 `Config.LLMConfig.LLMType` 建键 ⇒ 从 `Core.Common.LLMConfig` 手工构造配置再调 `create_llm_instance()` **必抛 `KeyError: <LLMType.OPEN_LLM>`** | 从 `Config.LLMConfig` 导入（正常 yaml→Config 路径不受影响） |

附带：provider 注册依赖 `import Core.Provider.OpenaiApi` 的**导入顺序**（`@register_provider` 装饰器在模块导入时执行）。

## 5. token 预算初估（待 W1 实测修正）

- 实测比例：**≈ 0.237 prompt tokens / 字符**；输出约为输入的 **11.7%**。
- PHEME 语料：10,022,314 字符 ⇒ **单次全读 ≈ 2.38M prompt tokens**。
- EraRAG 分层摘要 = chunk 摘要 + 树上卷，估放大 **1.5–3×**
  ⇒ **prompt 4–8M / completion 0.5–1.5M tokens**。
- 成本：GLM-4-Flash **¥0**；若换 DeepSeek 约 **¥10** 量级。
