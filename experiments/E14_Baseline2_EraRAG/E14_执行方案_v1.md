## 0. 一句话结论

**这个 baseline 不是 GPU 任务，是 API-token 任务。** 官方实现（`EverM0re/EraRAG-Official`）的依赖里装的是 `faiss-cpu` + `openai` + `llama-index-llms-ollama`，**默认就不吃卡**；真正花钱的是分层摘要的 token。按我们实测的语料体量估算，**整套跑完的现金成本在 ¥200–800 区间**（API 档最低可到 ¥150 上下），**4 卡 2080Ti 不稳不构成阻塞**——它最多用来跑 embedding，而 embedding 在 CPU 上也就几十分钟。**真正的成本是 5–8 个工作日的集成调试时间。**

## 3. 语料适配：我们的流 → EraRAG 的 chunk 流

EraRAG 的粒度是 **chunk = 短文档**，不是 cell。所以适配不是「换个表头」，是**换一层语义单位**。实测体量如下：

| 载体 | 单位 | 数量 | 文本量（实测） | 时间轴 | 用途 |
|---|---|---|---|---|---|
| **PHEME** | 推文 = chunk | **104,582** 条含文本（节点 105,747） | **10,022,314 字符**（均值 95.8） | ✅ snowflake ID **可反解毫秒** | **主载体**（英文，够大，真时间轴） |
| **CED** | 原帖 = chunk | **3,387** 条 | **372,855 字符**（均值 110.1） | ✅ 原帖 `publishTime` + 转发 `date` | **次载体**（中文对照） |
| CED 转发 | 流事件 | **1,275,180** 条 | ~8 字符/条（多数 **text 为空**） | ✅ `date` 字段（实测格式 `2012-09-16 15:05:11`） | **只作到达流，不作 chunk** |

**三条设计决定：**

1. **主载体用 PHEME。** CED 的转发文本几乎为空（实测样本 `text: ""`），把空 chunk 喂给摘要系统是退化输入、结论不可信。PHEME 有 104,582 条真文本 ⇒ 摘要层有活干。
2. **CED 的转发只当流。** 它对「到达顺序 / Δ 调度」有价值（真实时间戳），但对「chunk 质量」无价值。⇒ CED 那条线只作中文补充，规模小。
3. **到达顺序用真实时间戳**，不用合成流。PHEME 由 snowflake 反解、CED 由 `date`。这与 E1/E5 的口径一致（那边已经是真实时间轴）。

## 5. 算力需求分解 —— 哪些步骤真的要 GPU

| 步骤 | 绑定资源 | 2080Ti 够吗 | 说明 |
|---|---|---|---|
| **分层摘要（LLM）** | **API token** | ❌ 不需要卡 | 成本 99% 在这里。若改本地跑：7B 4-bit 在 2080Ti 上约 15–25 tok/s ⇒ 1×10⁷ token 需 **约 1 周**，不可行 |
| Chunk 嵌入 | 小 GPU / CPU | ✅ 绰绰有余 | BGE-M3 / MiniLM 级，10 万条几分钟到几十分钟；CPU 也可 |
| ANN 检索（LSH + kNN） | **CPU** | — | 官方依赖就是 `faiss-cpu` |
| 树结构/分区 | CPU | — | 纯算法 |
| 若跑 QA 评估的 reader | API | ❌ 不需要卡 | 与其原文一致（LLaMA-3.1-8B 作 reader） |

**结论：把 4 卡服务器从这条链路上摘掉，实验照样能做完。** 唯一需要它的是「本地 embedding」这一步，而那一步用 CPU 或单卡都能顶，且**天然可断点续跑**（逐 chunk 落盘）。

> 反过来：**如果你要的是"不依赖任何 API 的完全本地可复现"**（评审最友好，也最抗 API 停服），那 2080Ti 也顶不住——必须租一张 4090/A800 跑 vLLM 批量推理。这才是唯一值得花钱的地方。

## 6. 成本估算

### 6.1 token 量估算（自下而上，口径写明）

PHEME 原始文本 1×10⁷ 字符 ≈ **2.5M token**。EraRAG 是**分层摘要**：每个 chunk 至少进入一次摘要输入，且父层要重读子层摘要 ⇒ 构造成本 ≈ 原始 token × **3–5 倍**（含 prompt 与输出）。

| 项 | 估算 |
|---|---|
| PHEME 单次构建 | **≈ 10M token** |
| PHEME 10 次插入（Δ≈1%，只重摘要受影响段） | **≈ 1–3M token** |
| CED 单次构建（3,387 原帖） | **≈ 1–2M token** |
| **单次完整 run** | **≈ 15M token** |
| 3 seed × 2 载体 = 6 run | ≈ 90M token |
| Δ 扫描（4 档 × 2 载体） | ≈ +20M token |
| **合计（含 1.5× 返工余量）** | **≈ 120–150M token** |

### 6.2 四个档位

| 档位 | 做法 | 现金成本 | 时间 | 适配场景 |
|---|---|---|---|---|
| **A · API-only（推荐）** | LLM 走廉价 API；embedding 用本机 2080Ti 或 CPU | **¥150–700**（DeepSeek/Qwen 档约 ¥200–400；GPT-4o-mini 档约 ¥180–290） | 5–8 天 | 论文只要一个可信的成本点；最省钱 |
| **B · 混合** | API 跑摘要 + 租 1×4090 专跑 embedding/重跑 | ¥200–600 | 5–8 天 | 与 A 差别不大，仅当 embedding 量暴增 |
| **C · 全本地开源模型** | 1×4090（¥1.88/h）vLLM + Qwen2.5-7B/14B AWQ；或 1×A800-80G（¥5.59/h）跑 32B | **¥150–280**（4090，80–150 h）<br>**¥450–840**（A800） | 5–8 天 | **要"完全本地可复现"**、抗 API 停服；评审最友好 |
| **D · 加强：+GraphRAG/LightRAG 同语料** | 追加实体图类 baseline | **+¥3,000–30,000**（其构造成本在 10⁸–10⁹ token 量级） | +5 天 | **不建议全量**；要跑就**抽样 1/10**（+¥300–3,000） |

> 价格依据（2026-10 公开页）：AutoDL 官方价 **2080Ti ¥0.88/h、3090 ¥1.32/h、4090 ¥1.88/h、5090 ¥2.78/h、A800-80G ¥5.59/h、H800 ¥9.98/h**；第三方测评另报 4090 ¥1.58–3.49、A100 ¥3.6–6.5/h。关机不计 GPU 费，数据盘约 ¥0.1/GB/天。**价格随时变，下单前再核一次。**

**¥1,000 以内可以把这件事做完，且有很大冗余。** 真正的稀缺资源是集成调试的那 5–8 天，不是钱，也不是卡。

## 7. ⚠️ 口径风险（本方案最需要拍板的一处）

Baseline 对比最容易在**口径**上翻车。这里有一个**必须事先写死**的决定：

| 口径 | 含义 | 结果 |
|---|---|---|
| **口径 ①（维护口径，建议）** | 两边共用**同一份 LLM 抽取缓存**（`决策点3` §7.5 已要求缓存落盘），只比较「从已有声明 → 可查询结构」的维护代价 | 我们 **0 token**（纯重算受影响 cell）；EraRAG **>0 token**（重摘要）。**优势最大，也最公平**——因为它隔离出「谁在维护阶段烧 LLM」这一件事 |
| **口径 ②（端到端口径，并报）** | 两边都含抽取成本（同一份缓存，同价） | 差距变小但仍存在；数字更"保守"、更难被质疑 |

**做法：两个口径并报。** 只报 ① 会被说"你偷偷把抽取成本甩出去了"；只报 ② 会掩盖机制差异。

**第二处口径风险**：EraRAG 是**为长文档/QA 设计的**，我们喂的是**短文本流**（均值 96 字符）。这是移植，**必须写进 §7.9 Threats**：不能说"EraRAG 在我们任务上很差"，只能说"在其自身任务设定下，它在**流式维护代价**上的曲线形状是 X，且**不具备**状态/血缘能力"。措辞要守住这条线。

## 8. 建议

1. **建议做，走 A 档（API-only）。** 理由：¥1,000 以内、5–8 天，换来 §7.7 表里唯一还剩的 `[TBD-EXPERIMENT]`，且负结果（能力矩阵）本身是论文叙事的一部分（与 E10 并列）。这是当前**性价比最高的剩余项**。
2. **4 卡服务器不稳 ⇒ 不影响。** 它不在这条实验的关键路径上；W3 全部结果可由 API + CPU 产出。
3. **先做 W1 冒烟（1–2 天）+ W3b 能力矩阵（半天）。** 这两步**几乎零成本**、却不依赖任何大算力，一旦跑通，论文那个格子就有内容了；代价曲线（W3a）再决定跑多大规模。
4. **不做 D 档全量。** GraphRAG 类实体图 baseline 的 token 量级高两个数量级，会把预算从千元推到万元，收益边际。要加就抽样。
