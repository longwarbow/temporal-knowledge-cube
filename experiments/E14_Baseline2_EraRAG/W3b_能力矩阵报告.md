# E14 / W3b 能力矩阵：EraRAG 对「结构化分析查询」的能力边界

> 载体：PHEME 4 线程（Sydney×2 / Ottawa / Ferguson），**139 贴**（Phase1 建树 123 贴，Phase2 注入 16 条反驳贴）
> 环境：Windows / Python 3.9 / **CPU-only** / 本地 MiniLM(384) / 智谱 GLM-4-Flash
> 真值：`veracity_dict`（源贴真伪）+ `stance_dict`（回复立场 agreed/comment/appeal/**disagreed**）
> 脚本：`e14_w3b_capability.py`　原始结果：`W3b_能力矩阵.json`　日志：`_w3b.log`

---

## 0. 一句话结论

**EraRAG 的检索原语只有「语义 top-k」，没有任何结构化谓词入口；其索引元数据只存 `index`。**
因此对**时序 / 空间 / 事件归属 / 声明状态 / 血缘 / 聚合**六类分析查询，
它要么**答不出**（时间戳在检索层 100% 丢失），要么**跨事件串味**，要么**凭空编造聚合数字**——
而这三类失败恰好逐条对应本文 C1（维度演化）/ C2（可合并度量）/ C3（星座 + 血缘）。

## 1. 实验设计

| 组件 | 内容 | 是否用 LLM |
|---|---|---|
| **A 结构层扫描** | 枚举 EraRAG 检索原语枚举值、mode 列表、索引元数据 | 否（100% 确定性） |
| **B 事实存活** | 取真实检索上下文，检测 雪花id / ISO时间 / 时钟 / 地点词 是否存活 | 仅嵌入 |
| **C 谓词可检索性** | 5 类 × 3 查询 = 13 个自然语言分析查询，量化 P/R（对比 chance）与**线程纯度** | 仅嵌入 |
| **D 辟谣注入对照** | 先建**不含反驳贴**的树 → 再**增量注入 16 条 `disagreed` 回复** → 复查 | 仅嵌入 + 生成 |

**辟谣注入的用法**：主线程 `5027`（Sydney siege，源贴真伪 = **false**，即真谣言）含 **16 条 `disagreed`（反驳）**、3 条 agreed、12 条 comment。
Phase1 故意剔除这 16 条 → 树里「没有人反驳」；Phase2 用 `add=True` 增量插入 → 检验 EraRAG 有无「声明状态更新 + 可指认的反驳证据」。

## 2. 组件 A：结构层扫描（确定性，零 LLM）

**证据源**（可复现，非推测）：

| 取证件 | 内容 |
|---|---|
| `Core/Common/Constants.py :: class Retriever(Enum)` | `entity` / `relationship` / `chunk` / `community` / `subgraph` |
| `Core/Retriever/EntitiyRetriever.py :: self.mode_list` | `ppr` `vdb` `from_relation` `tf_df` `all` `by_neighbors` `link_entity` `get_all` `from_relation_by_agent` |
| `Core/Storage/TreeGraphStorage.py :: get_node_metadata()` | **`['index']`** |
| `Core/Retriever/MixRetriever.py :: retrieve_relevant_content(type, mode, **kwargs)` | 唯一注入通道是 `seed`（查询串） |

**谓词维度支持矩阵（全部为否）**：

| 谓词维度 | 原生支持 | 对应本文贡献 |
|---|---|---|
| time（时间 / 区间 / 时序） | ❌ | C1 时间维演化 / RQ1 时序知识立方体 |
| space（地点 / 行政区） | ❌ | C1 空间维（D10/D11/D15） |
| event / thread（事件 / 线程归属） | ❌ | C1 话题维 + 七操作（D18） |
| claim_status（真伪 / 立场 / 状态迁移） | ❌ | C2 + D2 状态迁移判据 |
| lineage（血缘 / 来源 / 引用链） | ❌ | **C3 + RQ2 谣言=血缘查询** |
| aggregation（计数 / 可合并度量） | ❌ | **C2 可合并度量代数 T1–T6** |

> 9 个 mode 全是**语义/图算子**（向量相似、PPR、TF-DF、邻居扩展），没有一个是**元数据谓词**。
> 索引元数据只有 `index` ⇒ **tweet id、时间戳、标签、引用关系在入库那一刻就被丢掉**，检索层无从恢复。

## 3. 组件 B：结构化事实存活率（13 个检索探针）

每次检索固定返回 **5 个树节点摘要**（`mean ctx 733 字符`）。

| 事实类型 | 存活率 | 说明 |
|---|---|---|
| **雪花 tweet id** | **0.000** | 检索上下文里 **一次都没出现**任何 id |
| **ISO 日期** | **0.000** | 同上 |
| **时钟时刻 (hh:mm)** | **0.000** | 同上 |
| 地点词 | 0.615 | 仅因城市名**恰好写在正文**里；不是字段检索 |

**★ 结论 B**：**身份与时间在检索层 100% 丢失**。
这不是"答得不好"，而是"**给 LLM 看的上下文里根本没有这两类信息**"——EraRAG 的摘要机制把它们都蒸发了。
（对照：本文 E13 实测血缘**不可从内容/时间推断**（ROC-AUC 0.5005）；此处进一步表明 EraRAG **连"时间"本身都不保留**。）

## 4. 组件 C：谓词可检索性（Phase1，N=123，top_k=5）

`P` = 检索集里属于真值目标集的比例；`chance` = 目标集占语料比例（随机基线）；`纯度` = 检索集来自最多线程的占比。

| 类 | 查询 | P | R | chance | 线程纯度 | 触达线程数 |
|---|---|---|---|---|---|---|
| T1 | 哪条回复最早、具体几点？ | 0.00 | 0.00 | 0.081 | 0.333 | 4 |
| T2 | 按时间顺序带时间戳总结 | 0.04 | 0.10 | 0.081 | 0.320 | 4 |
| T3 | 首末贴相隔几小时？ | 0.00 | 0.00 | 0.081 | 0.417 | 3 |
| S1 | 哪些贴关于悉尼 Lindt 咖啡馆 | 0.03 | 1.00 | 0.016 | 0.403 | 4 |
| S2 | 列出所有提到地点 | 0.032 | 1.00 | 0.016 | 0.435 | 4 |
| S3 | 哪些贴关于渥太华 | 0.03 | 1.00 | 0.016 | 0.448 | 4 |
| E1 | 哪些贴属于悉尼人质事件 | 0.30 | 0.176 | 0.138 | 0.400 | 3 |
| E2 | 按事件分组 | 0.132 | 0.529 | 0.138 | 0.382 | 4 |
| E3 | 单一事件还是多个 | 0.417 | 0.294 | 0.138 | 0.417 | 4 |
| C1 | 哪些回复反驳原说法 | 0.00 | 0.00 | 0.130 | 0.429 | 4 |
| C2 | 原说法被证实还是被反驳 | 0.00 | 0.00 | 0.130 | 0.600 | 3 |
| C3 | 列出质疑原帖的回复 | 0.00 | 0.00 | 0.130 | 0.800 | 2 |
| G1 | 共几条、其中几条反驳 | — | — | — | 0.364 | 4 |

**★ 结论 C**：
1. **时序类全灭**（P=0，最高 R=0.10）——因为树里没有时间（见 B）。
2. **空间类 recall=1.0 是假象**：目标集本身占了半个语料（Ottawa 关键词 67/123），检索也覆盖 60+ 条，
   precision ≈ 0.03 ≈ chance 0.016 ⇒ **无判别力**；而且这全靠正文里"恰好写了城市名"。
3. **事件归属类 P 0.13–0.42**，仅略高于 chance 0.138。
4. **线程纯度永远达不到 1.0**（0.32–0.80）：**任何一次检索都会混入 2–4 个线程的贴**——没有事件维，就无从"只看这一个事件"。

## 5. 组件 D：辟谣注入对照（Phase2，注入 16 条 `disagreed`）

增量注入成功：123 → **139 叶**、内部节点 17，耗时 71.2 s（索引已刷新）。

| 查询 | P | R | chance | **检索集线程分布** |
|---|---|---|---|---|
| C1 哪些回复反驳原说法 | 0.167 | 0.125 | 0.115 | `{145(Ferguson):6, 5027(目标):5, 5000:1}` |
| C2 原说法被证实还是被反驳 | 0.400 | 0.125 | 0.115 | `{5027:2, 145:3}` |
| C3 列出质疑原帖的回复 | 0.000 | 0.000 | 0.115 | `{145:4, 5000:1}` |

**★ 结论 D（本实验最锋利的一刀）**：

1. **反驳内容确实进了索引、也确实能被捞出**（`ctx[0]` = `@PhilSerrin "Jury still out." Yet, you made a direct inference that was recklessly false...`）——
   说明 EraRAG **不是"搜不到"**。
2. **但它没有任何事件/线程作用域**：问"**这个**论点有谁反驳"，检索出的 12 条里 **6 条来自完全无关的 Ferguson 线程**；
   C3 更极端——**5 条检索结果 0 条来自目标线程**。
3. **召回不足四分之一**（R = 0.125，16 条真值最多捞到 5 条），而 **precision ≈ chance**（P 0.0–0.4 vs 0.115）。
4. **没有"声明状态"概念**：注入的反驳贴只是又一个被嵌入的片段，系统**不产生**"该说法已被反驳"这一状态；
   也没有任何字段能**指认是哪一条**反驳了它（`id 存活率 = 0`，见 B）。

> 对照本课题：这正是 **RQ2「谣言 = 立方体上的血缘查询」**要解决的问题，也正是 **D2 状态迁移判据**要补的位。

## 6. 答案层证据（可直接引用进论文）

**① 自认无法做时序查询（T 类）**
> *"the provided context does not include any timestamps ... Without this information, **it is impossible to accurately answer the question**."*

**② 凭空编造聚合计数（G 类）**
> *"The collection of posts consists of **five distinct messages** ... Out of the five distinct posts, **four of them dispute the claim**."*
> 实际语料 **139 条**、反驳 **16 条**。EraRAG 把**检索到的 5 个片段当成了全集**并据此计算比例 —— **无聚合意识**。

**③ 跨事件串味（C 类）**
> 问 Sydney（线程 5027）"哪些回复反驳原说法"，答案给的是
> *"@larryelder Has that been proven?..."* / *"@PhilSerrin 'Jury still out.'..."* —— 全部来自 **Ferguson 线程（145）**。

**④ 把"摘要"当成"帖子"（E 类）**
> 列出"属于悉尼人质事件的帖子"，第 1 条是 *"Sydney cafe siege; concerns over terrorism; criticism of handling; debate on foreign policy..."* ——
> 这是**内部树节点的摘要**，不是任何一条真实帖子。用户无从分辨哪句是原文、哪句是模型的概括。

## 7. 对论文的落点

| 本实验结论 | 支撑论文哪一处 |
|---|---|
| 检索原语只有语义 top-k；元数据仅 `index` | §7.7 Baseline 表 #2（EraRAG 行）+ §7.9 Threats（"基线能力边界"） |
| 时间/身份在检索层 100% 丢失 | RQ1（时序知识立方体之必要性）+ C1 时间维 |
| 检索集线程纯度 <1.0、跨事件串味 | C1 话题维 + D18 七操作 + RQ2 |
| 把局部片段当全集、编造聚合计数 | **C2 两层度量 / 可合并度量代数 T1–T6** |
| 注入反驳后无状态、无指认 | D2 状态迁移判据 + **C3 血缘独立成层** |
| 结构层 6 谓词全缺 | "数仓工程纪律迁到 KB"这一总的 motivation |

**与 E13 的呼应**：E13 已实测"血缘不可从内容/时间推断"（ROC-AUC 0.5005，时间近邻 0.199）；
W3b 从**基线一侧**给出对称证据——EraRAG 同样**不保留时间与身份**，且**无任何谓词入口**。
两路证据合起来把 C3「血缘独立成层」从"设计选择"推成"**唯一可行解**"。
