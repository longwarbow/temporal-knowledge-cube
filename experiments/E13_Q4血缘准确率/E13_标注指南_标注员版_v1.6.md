## 0 你的任务

CSV 每行是一对推文 $(p, q)$：$p$ **较早**、$q$ **较晚**，两者来自**同一个真实事件**（`event` 列）。
**请判断 $q$ 相对 $p$ 的关系**，从 4 个标签中选**恰好一个**。你**不需要**猜这对是怎么挑出来的。

## 1 四个标签

| 标签 | 定义 |
|---|---|
| **DERIVE** | $q$ 是对 $p$ 的**转述 / 引用 / 转发 / 同文复制**，可追溯到 $p$（`RT @…`、`via @…`、近似逐字） |
| **SUPPORT** | $q$ **独立地**断言与 $p$ **相同的命题**（或同向的更强/更弱版本），无引用痕迹 |
| **CONFLICT** | $q$ 断言与 $p$ **不相容**的命题（不能同时为真） |
| **UNRELATED** | $q$ 在说别的事；从 $q$ 推不出关于 $p$ 命题的任何真值约束 |

## 2 ★ 判定顺序（按顺序走，**第一个命中的即结论**）

```
① T1  命题性检查   —— p 或 q 有任一方不含事实命题？
                      → UNRELATED（唯一例外：q 显式引用/照抄 p 文本 ⇒ DERIVE）
                        · 混合语力（悼念+事实从句）：忽略情绪，只要存在与 p 匹配的事实从句就继续往下走
② T2  隐含检查     —— q 是否只在否定 p 的隐含命题（祈使/邀请/建议被读出的事实）？
                      → UNRELATED
③ 槽位检查（**固定三步，顺序不得互换**）
   ③a T3 主体同一？   —— 主体不同 ⇒ UNRELATED（即使同属一个事件）
   ③b T4 谓词/情形同一？ —— 按 **A4 封闭族表**（§2.5）比较两侧数值的**谓词族**：
                          · 同族 ⇒ 同一槽位，继续 ③c
                          · 不同族 ⇒ UNRELATED
                          · 任一侧落不进族（或整句无数值）⇒ **A4 不适用**，继续 ③c 之后直接到 ④
   ③c T5 量兼容性？   —— 按 **A3**，**三步依次**：
                          ⓠ **前置门**：两侧的数**计量的是同类对象吗**（人 / 事件 / 场所 / 车辆 / 年）？
                             · 不同类 ⇒ **UNRELATED**（到此为止，不再看下面）
                          ⓐ 总数 vs **部分**（部分标记必须指向前一方所量的**同一总体**）⇒ 视为同命题，继续 ④
                          ⓑ 总数 vs 总数（互斥）⇒ CONFLICT
                          ⓒ 同值 / 无值 ⇒ 继续 ④
④ §2.1 派生检查     —— 同一命题内部：可追溯到 p？ → DERIVE ；否则 → SUPPORT
⑤ 兜底             —— 以上皆不中 → UNRELATED
```

> **为什么必须有顺序**：DERIVE / SUPPORT / CONFLICT 的定义**在边界上互相覆盖**。
> 只给定义而不给顺序，标注员会各按各的直觉选，κ 就掉下来。
> **冲突优先于派生**：若同时像"照抄"和"不相容"，取 **CONFLICT**。

### 2.1 术语定义

- **事实命题** = 可被第三方判真假的陈述。**不是命题** = 情绪、祝愿、祈祷、调侃、祈使、邀请、纯链接、纯提问。
- **槽位键** $= (\text{主体} \times \text{谓词} \times \text{时点})$。⚠️ **量（数值）不属于槽位键，它是槽位上的取值**。
- **逐字覆盖率** = 去掉 URL/`@`/表情/标点、统一小写后，**较短串的字符被较长串覆盖的比例**。

### 2.2 T1 · 命题性（含混合语力补丁）

若 $p$ 或 $q$ **任一方通篇不含事实命题** ⇒ **UNRELATED**。
**唯一例外**：$q$ 显式引用/照抄 $p$ 的文本 ⇒ **DERIVE**。
**混合语力**：既悼念又夹带事实从句时，**忽略情绪部分**，按匹配的事实从句继续判。

### 2.3 T2 · 不推断隐含命题

**不得**把祈使、邀请、建议、礼貌语读作断言。

### 2.4 ③a T3 · 主体同一

**主体不同 ⇒ UNRELATED**，即使同属一个事件。
⚠️ 同一场袭击的**不同场所 / 不同时点**（"总部枪击 12 死" vs "附近人质事件死 2"）**视为不同主体/情形** ⇒ UNRELATED。

### 2.5 ③b T4 · 谓词同一性（**A4 · 封闭族表版**）

**问句：两侧断言的谓词能否归并为"同一个状态/动作"？**

v1.5 的 A4 只有一张**反例清单（枚举、非穷尽）**；v1.6 把它升级为**有限封闭族表**：
先看两侧**各自数值绑到哪个谓词族**，再按族比较。

**★ 谓词族表（10 族，闭集——只有列在这里的形态被承认）**

| 族 `family_id` | 属性 | 取值 | 典型表面形式 |
|---|---|---|---|
| `FATALITY` | 生命状态 | 死亡 | killed / died / dead / shot dead / found dead / fatalities / toll / body |
| `INJURY` | 生命状态 | 受伤 | injured / wounded / hurt / hospitalized / critical / stable condition / paramedics |
| `AMBIG_PERSON` | 生命状态 | **存殁未定** | victim(s) / casualty(casualties) / affected |
| `CUSTODY_HELD` | 拘押状态 | 被扣押 | hostage(s) / held hostage / taken hostage / hostage situation / kidnapped / abducted / seized / detained |
| `CUSTODY_EXITED` | 拘押状态 | 脱离拘押 | escaped / fled / released / freed / rescued / **have left** |
| `PERPETRATOR_EXISTS` | 施害者 | 存在 / 数量 | gunman / shooter / suspect / attacker / terrorist / assailant / killer / bomber |
| `PERPETRATOR_IDENTITY` | 施害者 | 身份/背景/动机 | named / identified / background / motive / profile / convert / refugee / offender / record |
| `FORCE_SHOTS` | 武力 | 枪击 / 开枪 | gunfire / shots / shooting / shootout / opened fire / burst in |
| `FORCE_EXPLOSION` | 武力 | 爆炸 | explosion / blast / bomb / detonated / grenade |
| `POLICE_OPERATION` | 处置 | 警方行动 / 围困 | standoff / siege / lockdown / surrounded / holed up / stormed / raid / evacuated |

**★ 判定规则**

| 两侧数值的族 | 结果 |
|---|---|
| **同族** | **同一槽位** ⇒ 继续 ③c T5 |
| **不同族**（无论是否同属性） | **UNRELATED** |
| 任一侧的数值**落不进任何族**（含整句无家族数值） | **A4 不适用** ⇒ 落到 ④ §2.1 / ⑤ 兜底；**不得**据此判 UNRELATED |

**★★ 两条排序律（表和规则能用的前提）**

1. **度量类优先于泛化/角色类**：`12 people were killed` 的量纲是 `FATALITY` 而非 `person`。
2. **状态转移谓词优先于静态状态的名词论元**：`5 hostages escaped` 里被断言的是 `escaped`
   （`CUSTODY_EXITED`），而 `hostages`（`CUSTODY_HELD`）只是它的**论元** ⇒ **取 EXITED**。
   —— 这条是"扣押 ↔ 逃离"能被分开的关键；也正是**系统侧 v3 做不到 A4 的原因**（粗量纲把两者混为一类）。

**★ 判词**：**"同属一个真实事件"不构成"同一断言"的证据。**
一场人质事件里，"20 人被扣押"、"有人质逃离"、"发生枪击"、"医院收治伤者"是**四件不同的事**，
彼此**不互为真值约束**（一个为真不推出另一个的真假，也不排斥另一个）⇒ 两两之间一律 **UNRELATED**
（在表中就是**不同族**）。只有当两侧是**同一件事的不同说法**（同族 / 粗细）时才是同一槽位。

> **判别口诀**：**「$q$ 能不能给 $p$ 的命题提供真值约束？」**——仅在 ③a 主体相同之后使用。

**★ 未命中登记（v1.6 新增）——封闭世界假设的代价，必须可观测**
标注时若遇到**表外的新谓词** ⇒ 判 **UNRELATED**，并在 `label_notes` 写 **`pred-out-of-table: <谓词>`**。
这些记录**不是噪声**，而是**全量标注后回炉扩充族表**的依据。
（目的：把"判据漏了新族"变成**可观测事件**，而不是悄悄放过。）

**★ 已登记的缝（本轮**故意未解决**，全量标注时留意）**
- **上位词**：`AMBIG_PERSON`（victim / casualty）与 `FATALITY` / `INJURY` 的**归并关系未定**——
  `3 victims` 与 `3 dead` 目前判 **UNRELATED**（保守取值）。
- **身份/背景可由事实罗列表达**：`Haron Monis: fled Iran '96, suspect in ex-wife killing, 46 sex assaults`
  这类**无须身份关键词**的表述，封闭表**抓不到**（实测 `E13-0491`）⇒ 这类要靠 ③a T3（主体/情形）。
- **同族但"计量对象"不同**（人数 vs 起数）由 ③c 的 **A3-ⓠ** 负责，**不属于 A4**。

### 2.6 ③c T5 · 量的兼容性（**A3**）

**ⓠ 前置门（v1.5 新增，必须先过）：两侧的数计量的对象是同一类吗？**

| 计量对象 | 例 |
|---|---|
| 人（人数） | `1 hostage`、`11 dead`、`3 suspects` |
| **事件（起数）** | **`2 hostage situations`**、`3 attacks` |
| 场所（处数） | `2 locations`、`one building` |
| 车辆（架数） | `2 planes` |
| 年 / 时长 | `in 2009`、`15 years` |

- **不同类 ⇒ UNRELATED，到此为止**（例：`1 hostage`（人数=1 人）vs `2 hostage situations`（事件=2 起）
  ⇒ **UNRELATED**；**不要**因为"1 ⊂ 2"就判 SUPPORT）。
- 同类 ⇒ 继续下面三步。⚠️ **"人数 vs 起数"的错配是本项目最高的假阳性来源。**

**ⓐ/ⓑ 总数 vs 部分 / 总数 vs 总数：**

| 情形 | 判据（任一满足即"部分"） | 例 | 标签 |
|---|---|---|---|
| **总数 vs 部分** | ① 部分侧有**显式部分标记**（`these / those / among / of them / the N of / 其中`），**且该标记指向前一方所量的同一总体** | `5 hostages escaped` vs **`these two`** hostages escape | **SUPPORT** |
| | ② 总数侧是**下界 / 区间 / 模糊总量**（`at least N` / `N–M` / `dozens` / `multiple`），部分侧给出**更小的具体数**，**且对象同类** | **`At least 11 dead`** vs `4 cartoonists killed` | **SUPPORT** |
| | ③ 部分侧是**具指的少数子项**（可点名/可归类），总数侧为**无类别限定的同类总量** | `12 dead` vs **`The 4 French cartoonists killed`** | **SUPPORT** |
| **总数 vs 总数** | 两侧都自称**同一时点、同一范围的完整计数** | `11 dead` vs `12 dead`；`5 名人质` vs `6 名人质`；`多名枪手` vs `一名枪手` | **CONFLICT** |

> ⚠️ **① 的限定（v1.5 收紧）**：部分标记必须**指向前一方所量的那个总体**。
> 反例：$p$ = "11 dead including 2 police in **Paris shooting**"（量的是**枪击死者**），
> $q$ = "4 people reported dead **of six hostages**" —— 这里的 `of six hostages` 指的是**人质**，
> **不是 p 量的那个总体** ⇒ ① 不适用 ⇒ 两者是**不同事件** ⇒ **UNRELATED**。
>
> **模糊量词与具体数值一律可兼容（A2）**：`multiple suspects` vs `3 suspects` ⇒ 偏 **SUPPORT**，**不得** CONFLICT。
> **唯一例外**：模糊量词与**明确否定其存在**的一侧相遇 ⇒ 走 §2.8 极性。

### 2.7 §2.1 · 同命题内的 DERIVE vs SUPPORT（**A5**）

- 逐字覆盖率 **≥90%** 且**无任何新增/改变的事实性细节** ⇒ **DERIVE**。
- 覆盖率虽高但**存在新增/改变的事实细节** ⇒ **SUPPORT**。

**★ A5 · `@` 的两种角色（v1.5 新增裁定）**

| 形态 | 是什么 | 处理 |
|---|---|---|
| **句首的收件人 `@X`**（`@X 正文…`） | **收件人**，不属命题内容 | **先剥掉再算覆盖率** ⇒ 剥掉后逐字相同 ⇒ **DERIVE** |
| **来源标注 `via @X` / `RT @X` / `source: @X` / `据 @X`** | **归因**，是**新增的事实性细节**（"这条消息来自谁"） | **不得剥掉** ⇒ 判 **SUPPORT** |

> 依据：先导 `E13-0482` / `E13-0458` 两例，两通道**一致**判定"新增 `via @…` 来源 ⇒ SUPPORT"。
> 反例 A5 的错误用法：把 `… via @theblaze` 的 `@theblaze` 也当收件人剥掉 ⇒ 误判 DERIVE（`E13-0458`）。

- 覆盖率不足 ⇒ 按措辞/细节差异判 **SUPPORT**。
- ⚠️ **高相似 ≠ DERIVE**。拿不准判 SUPPORT 并写备注。

### 2.8 极性

同一槽位、量值相同或不可比，但一侧**明确否定**另一侧断言的**存在**（`no gunmen` / `not true` / `hoax`）
⇒ **CONFLICT**。仅有情绪/修辞性否定（反问、嘲讽）不构成极性 ⇒ 按 T1/T2 处理。

### 2.9 其它

- **CONFLICT 不判谁对**：两者都错也是一种 CONFLICT。
- **需要外部世界知识才能读出的关系** ⇒ UNRELATED，备注 `needs-world-knowledge`。
- **信息不足**（过短/纯链接/纯表情）⇒ 若已因 T1 命中则 UNRELATED；否则备注 `insufficient-info`。

## 3 置信度

`label_confidence` 填 **1（低）/ 2（中）/ 3（高）**。低置信样本**不会被删除**，会单独统计。请如实填写。

## 4 输出格式

CSV（UTF-8 带 BOM，逗号分隔，含表头）：

```
pair_id,label_relation,label_confidence,label_notes
```

- `label_relation` ∈ {`DERIVE`, `SUPPORT`, `CONFLICT`, `UNRELATED`}；
- `label_notes` 可为空；犹豫时请**写下来**并**注明命中的条款号/族名**
  （如 `A3-ⓠ` / `A3-ⓐ` / `A3-ⓑ` / `A4-同族 CUSTODY_HELD` / `A4-不同族 DEAD↔INJURY` / `A5`）；
  **遇到表外谓词**请写 **`pred-out-of-table: <谓词>`**（见 §2.5 未命中登记）；
- **必须把指定 CSV 的每一行都填满**，不得留空、不得增删行。

## 5 冻结条件

- **v1.6 为候选冻结版**。它通过「**靶向收敛 + 对照不被打散**」后，方可升级为**正式冻结版**
  （**全量标注开始后不得再改**）。
- ⚠️ **v1.6 的 A4 族表验证是在"被 v1.5 点名的那几条边界族"上做的 ⇒ in-sample，不算独立证据。**
  独立证据只能是全量标注时的**人类 κ**（承协议 §7 探针地位声明）。
- **A4 族表是"活表"**：全量标注中出现的 `pred-out-of-table` 记录**不导致回炉**，
  而是**扩充族表**（新增族须同时补进 `e13_predicate_match.py`，否则系统侧与判据不一致）。
- 若后续在全量标注中发现 v1.6 打散了新的对照项 ⇒ 回炉，并记录到判据修订迭代表。
